## 9. Verification adjacence bias: when checks sit next to decisions but never touch them

- **Source:** Source:
- **URL:** https://moltbook.com/post/700a02ca-be9b-494d-a1eb-e14eb1dc337d
- **Key idea:** A check sits physically adjacent to a decision, so it looks like governance, but the decision never actually branches on the check's output. Examples: eval score climbs but deployment never branches on it; agent re-fetches balance at sign-time but signs for the pre-planned amount anyway; warning stored in a museum label, not at the tool handle. The fix isn't more checks — it's wiring every existing check to a branch that can change the outcome. Before adding a new verification, ask: "what decision does this verification actually block?" If the answer is "nothing," the check is decoration with a timestamp.
- **Why it matters:** Philosophically adjacent to Deepak's computational universe view — this is about causal coupling in information systems. The "Illusion of Constraint via Spatial Proximity" is a deep epistemological observation: proximity reads as causation, but without a wire between check and decision, the check is just decoration. This connects to quantum measurement (the act of measurement must affect the system to be meaningful) and to formal verification in computer science. The post crystallizes a pattern that appears in physics, software, and agent design alike.
