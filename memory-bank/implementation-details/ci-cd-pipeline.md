# CI/CD Pipeline for cron-digests

*Created: 2026-05-18 11:25:00 IST*
*Last Updated: 2026-08-26 10:46:00 IST*
*Related Tasks: [T9](../tasks/T9.md), [T10](../tasks/T10.md)*

## Overview

The project has two deployment paths. The scheduled production path validates and deploys to the self-hosted Apache site; GitHub Actions validates, rebuilds, commits, and deploys GitHub Pages as the backup path on pushes to `main`.

## Primary Self-Hosted Deployment

The supported production command is:

```bash
bash scripts/deploy-live.sh
```

The arXiv, Web Science, and Moltbook cron jobs invoke this script after generation. It uses a lock to serialize deployments, rebuilds the JSON/SQLite index, runs digest validation, synchronizes `viewer/` to `/home/quantumofgravity/public_html/cron-digests/`, and checks the deployed index. The authoritative public URL is `https://quantumofgravity.com/cron-digests/`.

GitHub Pages remains a separately deployed backup at `https://space-cadet.github.io/cron-digests/`.

## Problem

1. **Index lag:** Before CI, `build-index.js` was only run manually. After a cron push, the viewer would show stale data until someone manually rebuilt and pushed the index.
2. **Validation gaps:** Digests were generated by isolated cron agents and pushed without automated validation. Format drift could break the viewer.
3. **Manual Pages deploy:** GitHub Pages required manual deployment or separate action setup.
4. **No feedback loop:** If a cron agent generated a malformed digest, it would reach the viewer before anyone noticed.

## Solution

### Two-Job Pipeline

| Job | Purpose | Triggers |
|-----|---------|----------|
| `validate-and-index` | Validate digests → rebuild index → auto-commit | Every push to main, PR, manual dispatch |
| `deploy` | Deploy `viewer/` directory to GitHub Pages | Only after `validate-and-index` succeeds |

### Validation Gate

```yaml
- name: Validate digests
  run: node scripts/validate-digest.js
```

If `validate-digest.js` finds any errors (malformed headers, wrong item counts, missing fields), the job exits with code 1. The `deploy` job has `needs: validate-and-index`, so it never runs if validation fails.

### Index Auto-Rebuild

```yaml
- name: Build index
  run: node scripts/build-index.js
  continue-on-error: true

- name: Commit all changes
  run: |
    git config user.name "github-actions[bot]"
    git config user.email "github-actions[bot]@users.noreply.github.com"
    git add -A arxiv/ web-science/ viewer/
    if ! git diff --cached --quiet; then
      git commit -m "chore(viewer): auto-rebuild index [ci skip]"
      git push
    fi
```

**Key changes (2026-05-21):**
- `continue-on-error: true` on build step — index build failures don't block deploy
- Stages ALL changes (`arxiv/`, `web-science/`, `viewer/`) not just index files — ensures cron-pushed digests are committed even if index build fails
- `[ci skip]` prevents infinite CI loops

The `[ci skip]` prefix in the commit message prevents the push from triggering another CI run, avoiding infinite loops.

### GitHub Pages Deploy

```yaml
deploy:
  needs: validate-and-index
  runs-on: ubuntu-latest
  permissions:
    pages: write
    id-token: write
  steps:
    - name: Setup Pages
      uses: actions/configure-pages@v5
    - name: Upload artifact
      uses: actions/upload-pages-artifact@v3
      with:
        path: viewer/
    - name: Deploy to GitHub Pages
      uses: actions/deploy-pages@v4
```

Only the `viewer/` directory is uploaded as the Pages artifact. The rest of the repo (scripts, digests, etc.) is not deployed.

## Implementation Details

### Workflow File

```yaml
# .github/workflows/ci.yml
name: Validate, Index, and Deploy

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: write
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  validate-and-index:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
      - run: node scripts/validate-digest.js
      - run: node scripts/build-index.js
      - run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add viewer/index.json viewer/index.db
          if ! git diff --cached --quiet; then
            git commit -m "chore(viewer): auto-rebuild index [ci skip]"
            git push
          fi

  deploy:
    needs: validate-and-index
    runs-on: ubuntu-latest
    steps:
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: viewer/
      - uses: actions/deploy-pages@v4
```

### Key Design Decisions

1. **Separate jobs for validation and deploy:** Keeps concerns separated. The deploy job only handles Pages; validation/index handles data integrity.
2. **`[ci skip]` for auto-commits:** Essential to prevent infinite CI loops. The commit that updates the index would otherwise trigger another push → another CI run → another commit.
3. **`permissions` block at workflow level:** Grants `contents:write` (for auto-commit), `pages:write` and `id-token:write` (for Pages deploy).
4. **`concurrency: group: pages`:** Prevents multiple deploys from conflicting. If two pushes happen close together, the second waits for the first deploy to finish.
5. **`needs: validate-and-index`:** The deploy job only runs if validation passes. A broken digest will never reach the viewer.

## Security Notes

1. **No secrets in workflow:** The workflow uses only built-in GitHub Actions tokens (`GITHUB_TOKEN` via `permissions`). No personal access tokens or external secrets.
2. **Minimal permissions:** Only `contents:write`, `pages:write`, and `id-token:write` are granted. No `actions:write` or other elevated permissions.
3. **Auto-commit user:** Uses the standard `github-actions[bot]` identity, clearly marking automated commits.
