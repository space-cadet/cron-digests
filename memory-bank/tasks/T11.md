## Problem Statement

The May 25 arXiv morning digest contained 12 papers with **real arXiv IDs but entirely hallucinated metadata**:
- Paper 2605.23375: claimed "Intertwiners in LQG" → actual "Counting Degrees of Freedom in Open Effective Theories"
- Paper 2605.23886: claimed "Page Curve from Replica Wormholes" → actual "Heterotic Strings on Enriques Surfaces"
- Paper 2605.23900: claimed "Non-Commutative BTZ Black Hole" → actual "What to do with a Ricci-flat Calabi–Yau metric?"
- Paper 2605.22862: claimed "Gravitational Self-Force" → actual "Constraining Black Hole Parameters in Non-Commutative Geometry using Machine Learning"
- Paper 2605.23894: claimed "CSS LDPC Codes from Finite Incidence Structures" → actual "A Two-Branch Finite-Field Construction for Regular CSS LDPC Bases"
- Plus 9 more entries with wrong authors

**Root cause:** The cron subagent extracted IDs from arXiv listing pages but invented metadata from training data instead of using `web_fetch` to verify each paper against the actual arXiv API/abstract page.

**Historical audit:** Spot-checked May 22, May 20, May 15 — all correct. The hallucination was isolated to May 25.

## Root Cause

| Issue | Root Cause | Impact |
|-------|-----------|--------|
| Hallucinated titles | Agent relied on training data, did not verify via `web_fetch` | Completely wrong paper descriptions in digest |
| Hallucinated authors | Same as above | Wrong author attribution |
| Hallucinated abstracts | Same as above | Misleading relevance assessments |

## Solution

### 1. Regenerated May 25 Digest

- Used subagent to verify ALL 12 papers via `web_fetch` against arXiv abstract pages
- Every title, author list, abstract, and category was confirmed against live arXiv data
- Rewrote digest with verified metadata
- Committed as `arxiv: 2026-05-25` (corrected)

### 2. Updated Cron Job Prompt with Non-Negotiable Verification Rules

Added to arXiv cron payload:
- **Step 1:** Browse arXiv listing pages to get IDs
- **Step 2:** Read previous digest for deduplication
- **Step 3:** `MUST use web_fetch` on every candidate paper's abstract page before including it
- **Step 4:** `You may NOT include any paper whose metadata you have not verified via web_fetch` — hard prohibition
- **URL RULE (non-negotiable):** All paper links MUST use `https://arxivite.org/abs/<id>`. Even though arXiv API returns `arxiv.org` URLs, you MUST rewrite them.

### 3. Fixed All Historical arXiv URLs

Changed all `arxiv.org` links in digests and template to `arxivite.org`:
- `arxiv/2026-05-25.md` — all URLs updated
- `TEMPLATE.md` — example URLs updated
- Cron prompt — explicit rewrite rule added

## Lessons Learned

1. **IDs are not enough.** Even real arXiv IDs can be paired with hallucinated metadata if the agent doesn't verify.
2. **`web_fetch` must be mandatory, not optional.** The cron prompt must explicitly prohibit inclusion without verification.
3. **Spot-check history when an error is found.** May 25 was an isolated incident, not a systemic problem.
4. **URL rewriting needs explicit rules.** arXiv API returns `arxiv.org` URLs; the cron agent must rewrite them to `arxivite.org` before writing the digest.
