## Problem Statement

The cron-digest system was failing silently on a daily basis:

1. **Web Science cron got stuck** — Agent spent 37 minutes trying to fetch APS News and Scientific American directly via `web_fetch`. Both sites block bots. Never wrote or pushed anything.
2. **CI workflow was fragile** — If `build-index.js` failed, the entire workflow died and new digests pushed by cron were never committed. The commit step only staged `viewer/index.json` and `viewer/index.db`, ignoring new digest files in `arxiv/` and `web-science/`.
3. **Validator was too strict** — `scripts/validate-digest.js` flagged arxiv digests for having fewer entries than the `items_found` header value. But arxiv intentionally reports total announcement size, not selected entries.

## Root Causes

| Issue | Root Cause | Impact |
|-------|-----------|--------|
| Web science digest missing | Agent tried blocked sites directly, no fallback | No digest generated, viewer stale |
| Index not rebuilt | CI commit step only staged index files | Cron-pushed digests never committed |
| CI blocked by index failure | No `continue-on-error` on build step | Deploy never ran, everything stuck |
| Validator false positives | `items_found` check applied to all digest types | arxiv digests wrongly flagged |

## Solution

### 1. Fixed Validator (`scripts/validate-digest.js`)

**Change:** Skip `items_found` accuracy check for arxiv digests.

```javascript
// Line ~280
if (digestType !== 'arxiv') {
  // Only check items_found for non-arxiv digests
  // arxiv reports total announcement size, not selected entries
}
```

**Rationale:** arxiv digests intentionally include only selected papers from a much larger announcement. The `items_found` header reports the total announcement size for context, not the number of entries actually written.

### 2. Hardened CI Workflow (`.github/workflows/ci.yml`)

**Change 1:** `continue-on-error: true` on build-index step.

```yaml
- name: Build index
  run: node scripts/build-index.js
  continue-on-error: true
```

**Rationale:** Index build failures (e.g., missing dependency, malformed digest edge case) should not block deployment of the viewer. The commit step will still stage digest files.

**Change 2:** Commit step now stages ALL changes, not just index files.

```yaml
- name: Commit all changes
  run: |
    git add -A arxiv/ web-science/ viewer/
    if ! git diff --cached --quiet; then
      git commit -m "chore(viewer): auto-rebuild index [ci skip]"
      git push
    fi
```

**Rationale:** Cron agents push new digest files but don't always rebuild the index. The CI must commit these files or they sit uncommitted in the working tree forever. Staging `arxiv/` and `web-science/` ensures cron output is never lost.

### 3. Updated Web Science Cron Prompt

**Old prompt:** "Rotate through site pairs... fetch headlines... summarize..."

**New prompt:** "Use CloakBrowser script. If it fails, fallback to `web_fetch` for Phys.org + ScienceDaily. Commit and push in 10 minutes max."

**Key directives:**
- **Exact command:** `xvfb-run --auto-servernum --server-args='-screen 0 1280x720x24' node scripts/generate-web-science-cloak.mjs`
- **5-minute fallback:** If CloakBrowser fails, use `web_fetch` for the same two sites
- **Hard stop:** Do not try APS News or Scientific American directly (they block)
- **Must push:** Digest is useless until committed and pushed

**Rationale:** The agent was wasting time on creative problem-solving ("maybe if I try a different approach...") instead of executing a known-working script and falling back gracefully.

## Lessons Learned

1. **Bot-blocking is real.** Major science sites (APS, Scientific American, Nature) aggressively block non-browser requests. CloakBrowser with headed mode + xvfb is required on VPS.
2. **CI must be resilient.** A single failing step should not cascade into total system failure. `continue-on-error` and broad staging are essential for cron-driven repos.
3. **Cron prompts need exact commands.** "Fetch headlines" is too vague. "Run this exact bash command, fallback to this, push in 10 minutes" works.
4. **Validation must understand domain semantics.** `items_found` means different things for arxiv (announcement size) vs web-science (actual articles fetched).
