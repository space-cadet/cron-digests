## Problem

The arXiv digest cron job generated summaries using a heuristic: first 2 sentences of the abstract. This produced poor quality summaries that were just copied openings rather than capturing actual paper contributions.

## Solution

Updated the cron job payload to spawn a K2.7 subagent after digest generation, which rewrites all summaries to capture actual contribution/result/method.

## Implementation

**Cron job:** `e732d817-832f-4198-a2e7-1d081d285a81` — "arXiv Morning Digest"
**Schedule:** Tue-Sat 7:11 IST (Asia/Kolkata)
**Model:** `kimi/k2p6` for main agent, `kimi/k2.7-code` for subagent

### Updated Payload

```
Step 1: Run arxiv-digest-full.sh (generates digest with simple summaries)
Step 2: Read generated digest
Step 3: Spawn K2.7 subagent to rewrite all summaries
Step 4: Report to Telegram with digest stats + "Summaries: fixed via subagent"
```

### Subagent Task

```
Read the arXiv digest at ~/.openclaw/workspace/code/cron-digests/arxiv/YYYY-MM-DD.md.
For each paper, the Summary field is the first 2 sentences of the Abstract.
Rewrite each Summary to capture the actual contribution/result/method in 1-2 sentences.
Keep LaTeX math. Save the file.
Run `node scripts/build-index.js` from repo root.
Git commit as 'fix: AI summaries for YYYY-MM-DD' and push to origin main.
```

## Lessons Learned

1. **Subagent model matters** — K2.7-code handles batch file editing reliably; K2.6 had issues with complex multi-file tasks.
2. **Subagent timeout** — 0 (no timeout) to allow sufficient time for LLM generation.
3. **Light context** — Main agent uses `lightContext: true` since it just orchestrates, not reasons deeply.
