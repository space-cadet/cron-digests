## Details
User requested a manual rerun of the arXiv digest for 2026-06-05 with proper throttling between API calls to avoid 429 (Too Many Requests) errors. The original morning cron-generated digest had 15 papers but the cron job itself had been erroring for 4 consecutive runs.

## Root Cause
The `scripts/fetch-arxiv-html.py` script was making rapid sequential requests to arxiv.org without any delay between category fetches. When combined with abstract fetching for the digest, this triggered rate limiting.

## Fix Applied
- Added `import time` and `time.sleep(3)` between the four category fetch requests in `fetch-arxiv-html.py`
- Built a separate throttled abstract fetcher (`/tmp/fetch-abstracts.py`) using curl with 3-second delays between each paper's abstract page request
- Fetched 12 paper abstracts from `arxiv.org/abs/` pages (not API) with deterministic throttling
- Verified zero 429 errors throughout the process
