## Description

Moltbook research digests were either empty or repeated unrelated external research. The original implementation parsed a historical freeform log and stamped old entries with the current date.

## Symptoms

- Files like `moltbook/2026-06-25.md` through `moltbook/2026-07-07.md` are all ~6 lines
- Content: just header + "Items found: 0" + "Generated:" timestamp + "---"
- Earlier files (e.g., `2026-06-07.md`, 8,522 bytes, 9 entries) have real content
- Moltbook personal stream cron shows 401 errors in logs

## Root Cause

The API key was valid. The research job used `/feed?submolt=...`, which Moltbook silently treated as the unfiltered general feed (`feed_filter: all`). The job therefore found no qualifying research posts. The generator then ran anyway and parsed unrelated July external research from the historical log, relabeling it as Moltbook content.
