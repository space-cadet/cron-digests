# T16: Cron-Digests Bug Fixes — Math, Tags, Summaries

**Status:** ✅ Completed
**Completed:** 2026-06-19 03:12 IST
**Started:** 2026-06-19 01:52 IST

## Problem Statement

Three independent bugs identified in the cron-digests viewer:

1. **KaTeX math not rendering** — LaTeX equations in arXiv abstracts displayed as raw `$...$` and `$$...$$` text in both card previews and modal views.
2. **Tag/chip display broken** — Category chips in modal showed nonsense words (e.g., "a", "or", "causal") instead of actual categories. See screenshot [telegram:file/AgACAgUAAxkBAAJEw2o0o6q0i5aqzPC6KoJ3sLxEaXf6AAKmDmsbTTSoVcC4hT_XtwuaAQADAgADdwADPAQ].
3. **Summaries copied from abstracts** — The "Summary" field was simply the first 2 sentences of the Abstract, not an actual summary. Affected all digests back to at least June 10.

## Root Causes

1. **Math**: No KaTeX library loaded in viewer/index.html. Needed CSS + JS + renderMathInElement() calls.
2. **Tags**: Regex `\*\*Categories:\*\*\s*(.+)` used `\s*` which matches newlines in JavaScript. When Categories field was empty (`- **Categories:** `), the regex consumed the newline and captured the Abstract line instead. Subsequent `split(',')` + `split(' ')[0]` logic extracted first words from abstract fragments, producing garbage chips.
3. **Summaries**: `scripts/arxiv-digest-full.sh` used `re.split(r'(?<=[.!?])\s+', abstract)[:2]` — a heuristic that copies the first 2 sentences, which are typically introductory/background rather than actual contribution.

## Fixes Applied

### 1. KaTeX Math Rendering

**File:** `viewer/index.html`

Added to `<head>`:
```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/katex@0.16.21/dist/katex.min.css" integrity="sha384-..." crossorigin="anonymous">
<script defer src="https://cdn.jsdelivr.net/npm/katex@0.16.21/dist/katex.min.js" integrity="sha384-..." crossorigin="anonymous"></script>
<script defer src="https://cdn.jsdelivr.net/npm/katex@0.16.21/dist/contrib/auto-render.min.js" integrity="sha384-..." crossorigin="anonymous"></script>
```

Added `renderMathInElement()` call in:
- `showModal()` — after modal content is injected
- `renderDigests()` — after card grid is built

Delimiters: `$$...$$`, `$...$`, `\[...\]`, `\(...\)`

**Note:** SRI integrity hashes must be verified against actual CDN files. Wrong hashes cause browsers to block script loading (observed during initial attempt).

### 2. Tag/Chip Bug

**Files fixed:**
- `viewer/index.html` — `extractCategoryChips()` regex
- `scripts/build-index.js` — 5 regexes (`summary`, `relevance`, `tags` entry parsers + `sitesMatch`, `focusMatch` header parsers)
- `scripts/validate-digest.js` — same 5 regexes

**Pattern changed:** `\*\*Categories:\*\*\s*(.+)` → `\*\*Categories:\*\*[ \t]*([^\n]*)`

- `[ \t]*` — only horizontal whitespace (not newlines)
- `([^\n]*)` — capture up to end of line

**Index rebuilt** — corrupted entry (paper #9 in 2026-06-16, "Beyond the Metric...") now correctly has `Categories: ''` instead of abstract text.

## Lessons Learned

1. **Regex `\s*` matches newlines** in JavaScript `match()` with `/m` flag. This is a subtle trap that caused a cascading bug (empty field → cross-line match → corrupt data → broken UI).
2. **SRI hashes must be verified** against actual CDN files, not copied from documentation.
3. **K2.7 subagents are effective** for batch content generation tasks (60 summaries in ~3 minutes each file).
4. **Gateway restarts can kill long-running subagents** — split work across multiple shorter subagents for resilience.
