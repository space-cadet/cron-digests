## Context
- **Why CI?** Before this, the index was only rebuilt manually. After a cron push, the viewer would show stale data until someone ran `build-index.js` locally and pushed. Now it's fully automated.
- **Validation gate:** If `validate-digest.js` finds errors, the CI job exits with code 1 and the Pages deploy job never runs. This prevents broken digests from reaching the viewer.
- **Auto-commit with [ci skip]:** The CI commits updated index files but skips triggering another CI run, preventing infinite loops.
- **Deploy from viewer/ directory:** Only the viewer files are uploaded as the Pages artifact, not the entire repo.
