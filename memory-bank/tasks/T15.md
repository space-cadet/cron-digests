## Problem Statement

Starting around 2026-05-11, arXiv digests began showing `[Abstract extraction failed]` for all papers. Upon investigation, the root cause was an **arXiv HTML structure change**: abstracts were no longer wrapped in `<p>` tags, instead sitting directly after `<span class="descriptor">Abstract:</span>`. The old regex `.*?<p>(.*?)</p>.*?</blockquote>` failed to match, causing all abstracts to show as failed.

A secondary issue was discovered: **category extraction was also broken** in `scripts/fetch-arxiv-html.py`. The regex `([a-zA-Z\-]+(?:\.[a-zA-Z\-]+)?)(?:\s*\([^)]\))?` greedily consumed text before the parenthetical category codes, causing all categories to come up empty.

## Impact Assessment

- **6 recent digests** affected: 2026-06-09, 2026-06-10, 2026-06-11, 2026-06-12, 2026-06-13, 2026-06-16
- **All digests since ~2026-05-11** potentially had empty categories (category extraction was already broken)
- **90+ digests** from May 11–26 had no abstracts (the script was added June 7, but the HTML structure change happened earlier)

## Root Cause Analysis

### Abstract Extraction Failure
1. arXiv changed their abstract HTML from:
   ```html
   <blockquote class="abstract mathjax"><span class="descriptor">Abstract:</span><p>Abstract text here</p></blockquote>
   ```
   to:
   ```html
   <blockquote class="abstract mathjax"><span class="descriptor">Abstract:</span>Abstract text here</blockquote>
   ```
2. The regex in `scripts/arxiv-digest-full.sh` only matched the old `<p>` wrapper pattern.
3. All 6 recent digests showed `[Abstract extraction failed]` for every paper.

### Category Extraction Failure
1. arXiv HTML format for subjects: `<span class="primary-subject">High Energy Physics - Theory (hep-th)</span>`
2. The regex `([a-zA-Z\-]+(?:\.[a-zA-Z\-]+)?)(?:\s*\([^)]\))?` tried to match the category code with optional parenthetical group.
3. Due to greediness and the `[^a-zA-Z-]` boundary, the regex matched the text BEFORE the parenthesis and never captured the code inside.
4. Result: all papers had empty categories in the JSON pre-fetch data.

## Fixes Applied

### Fix 1: Abstract Extraction Regex (arxiv-digest-full.sh)
- **File:** `scripts/arxiv-digest-full.sh`
- **Change:** Added new regex pattern that matches abstract text directly after `<span class="descriptor">Abstract:</span>`, with the old `<p>` pattern as fallback.
- **New pattern:** `.*?<span class="descriptor">Abstract:</span>(.*?)</blockquote>`
- **Fallback:** `.*?<p>(.*?)</p>.*?</blockquote>` (for old format, if arXiv reverts)

### Fix 2: Category Extraction Regex (fetch-arxiv-html.py)
- **File:** `scripts/fetch-arxiv-html.py`
- **Change:** Rewrote category extraction to first extract codes from within parentheses (e.g., `(hep-th)`), with a fallback for bare codes if no parentheses are found.
- **New pattern:** `\(([a-zA-Z\-]+(?:\.[a-zA-Z\-]+)?)\)`
- **Fallback:** `(?<![a-zA-Z.])([a-zA-Z\-]+(?:\.[a-zA-Z\-]+)?)(?![a-zA-Z.])` with skip list for CSS class names

### Fix 3: Retroactive Abstract Repair
- **Files:** `arxiv/2026-06-09.md` through `arxiv/2026-06-13.md`, `arxiv/2026-06-16.md`
- **Action:** Re-fetched all 90 missing abstracts (15 papers × 6 digests) using the fixed regex.
- **Tool:** Python script `/tmp/fix-abstracts-v2.py` with 0.5s delay between requests to be polite to arXiv servers.
- **Result:** All 6 digests now have complete abstracts and summaries.

## Lessons Learned

1. **arXiv HTML is not stable.** Both `<p>` tag wrappers and category formatting have changed over time. All regex-based scraping should have multiple fallback patterns.
2. **Greedy regex is dangerous.** The category extraction regex consumed text it shouldn't have because of greedy matching and lack of proper word boundaries.
3. **Monitor digest quality.** The abstract failure went unnoticed for ~11 days (June 5–16). The category failure went unnoticed for ~1 month (May 11–June 16). A quality check (e.g., "alert if >20% abstracts failed") should be added to the cron job or heartbeat.
4. **Parenthetical extraction is reliable.** Category codes inside `(hep-th)` are unambiguous. Extracting from inside parentheses is more robust than trying to match the code with optional parenthetical.

## Next Actions

2. Consider adding a "fallback URL" for abstract extraction (e.g., arXiv API as backup if HTML scraping fails).
3. Review historical digests from May 11–26 for potential category backfill (lower priority since categories are metadata, not content).
